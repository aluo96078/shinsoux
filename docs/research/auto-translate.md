# 自動啟動翻譯評估（2026-11-16）

## 問題
目前要翻譯，得在閱讀器叫出工具列 → 點翻譯按鈕 → 開啟面板 → 打開開關 → 關閉面板，而且每部作品都要做一次。能否判斷「這部作品不是目標語言」就自動開始翻譯，並讓使用者決定要不要啟用這個功能？

## 目標語言
已有 `ReaderTranslation.targetLanguage(tag)`，可以把 App 語言或系統語言對應到引擎支援的語言（繁中、簡中、日、韓、英，找不到時用繁中）。小說面板目前已經用系統語言作為預設的翻譯目標。建議改用 App 語言（`general.languagePreference`），設為「跟隨系統」時再用系統語言。

## 判斷作品語言
| 類型 | 可用的訊號 | 可靠度 |
|---|---|---|
| 小說 | 章節本文：已有 `ReaderTranslation.detectLanguage(text)`，依文字的書寫系統判斷（假名→日、諺文→韓、漢字→中、拉丁字母→英） | 高。不過簡體和繁體分不出來：被判成簡中時，繁中使用者也會自動翻譯成繁中，等於簡轉繁，通常正是使用者想要的 |
| 漫畫（擴充來源） | 來源的語言（`BrowseSource.language`，例如 ja、en、zh） | 高；若來源標示為 all、multi 則無法判斷 |
| 漫畫（本機匯入、多語言來源） | 偵測加 OCR 前 1～2 頁，看辨識出來的文字裡假名的比例 | 中等，約多花 1 秒；需要已下載辨識模型 |

限制：漫畫的 OCR 只讀得懂日文，所以**漫畫只有「日文作品」能自動翻譯**。英文、韓文、中文漫畫即使判斷出來也無法翻譯，直接略過，不顯示任何提示。

> 更新（多語言 P1 之後）：漫畫也能讀中文與英文頁面（docs/research/manga-multilingual.md）。來源標示為日、中、英的漫畫都會自動翻譯；來源沒標示語言時，仍只靠假名比例判斷日文。

## 什麼時候自動開始
滿足以下全部條件時，打開章節就自動開始翻譯：
1. 「自動翻譯」已開啟（全域開關），而且作品語言在「要自動翻譯的語言」中被勾選（預設全部勾選；未勾選的語言存在 `auto.skipped` 偏好裡，依引擎語言碼，例如 `zh-Hans`）。
2. 這部作品**從未設定過**翻譯（`translation.settings(workKey) == null`）。使用者對某部作品手動關掉之後就會記住，不會再自動打開；手動開過的作品則維持原本的設定。
3. 作品語言 ≠ 目標語言，而且翻譯服務支援這組語言。
4. 所需的模型都已下載。若還沒下載，不會自動下載幾百 MB，改為顯示現有的提示「需要先下載…，點此下載」，點一下就能下載並開始翻譯。

自動開始時，閱讀器頂端照常顯示進度提示，點一下就能打開面板關掉翻譯（只關這部作品）。

## 付費服務
自動翻譯可能在使用者沒注意時產生費用。建議：
- 自動翻譯開關底下加一個選項「付費服務也自動翻譯」，預設關閉。關閉時，若翻譯服務是 DeepL、Google、Azure 或 AI 模型，就不自動開始，只顯示「點此翻譯」的提示。
- 每日額度照常生效。

## 設定位置
「更多 → 翻譯」首頁最上方加一個開關：**自動翻譯外語作品**，附說明「打開不是〇〇（目標語言）的作品時自動翻譯。對單一作品關掉翻譯後，就不會再自動打開。」以及上面提到的付費服務選項。預設：開啟，付費服務不自動。

## 順帶可以簡化的地方
- 工具列的翻譯按鈕改成直接切換開或關，長按（桌機為右鍵）才開啟面板。
- 預先翻譯佇列也可以沿用同一套判斷：自動翻譯的作品，後續章節照常預先翻譯。

## 工作量
- `TranslationPreferences` 和儲存層：新增 `autoTranslate` 與 `autoTranslatePaid` 兩個欄位，備份與同步也要跟著處理。
- 共用判斷函式：`autoTranslateTarget(workLanguage, appLanguage, preferences)`，加上單元測試。
- 小說：`rememberNovelTranslation` 在 restore 時，若設定為 null 且符合條件，就用 enabled=true 開始（不需要寫入設定，等使用者實際操作再存，避免誤判後被永久記住）。
- 漫畫：`rememberMangaReaderTranslation` 的 `load()` 用同樣的判斷；來源語言從 `appServices.browse.sources` 取得，本機匯入與多語言來源則先做取樣辨識。
- UI：翻譯首頁的開關、字串、工具列按鈕行為。
- 預估中等規模，平台層不需要改動。

## 簡繁轉換（2026-11-16 更新）
簡體與繁體中文之間不再走翻譯服務，一律在裝置上逐詞轉換：
- **轉換表**：取自 OpenCC（Apache-2.0）的 s2twp／tw2sp，簡轉繁時也套用台灣用詞（軟件→軟體、打印機→印表機），繁轉簡則反過來套用大陸用詞。`tools/chinese-script/build_dictionary.py` 會下載固定版本的字典，刪掉「表中其餘條目在任何句子裡都能轉出相同結果」的詞組，再輸出 `composeResources/files/chinese-script.txt`（約 1 MB）。逐詞轉換由左往右取最長的詞，所以詞組刪掉後，原本位置裡的比對不能延伸到詞組後面：像「里面」能避免「里面包含」被讀成「面包」而轉成「裡麵包含」。先刪的詞組可能在後來刪掉其他詞組後變成必要，因此會用最終的表反覆檢查，直到全部成立。
- **路由**：`ReaderTranslation` 遇到 zh-Hans ↔ zh-Hant 時改用 `ChineseScriptProvider`（`paid = false`，紀錄的 provider 為 `chinese-script`）。這組語言不需要金鑰或模型、不計入付費的每日額度，也不受「付費服務也自動翻譯」開關限制。
- **預設不自動轉換**：App 語言是中文的讀者通常兩種寫法都能讀，所以另一種寫法預設不自動轉換（`autoTranslateOtherScript`，存在 `pref.auto.otherScript`，預設關閉）。在「要自動翻譯的語言」勾選另一種寫法即開啟；這個勾選只看這項設定，不看舊的略過清單。手動在翻譯面板開啟仍可轉換。
- **漫畫**：已繪製頁面的鍵也改用這組轉換（`engineIdentity(from, to)`），因此切換翻譯服務時不必重畫。
- **分辨簡繁**：統計只有一種寫法的常用字（这/這、们/們、说/說），數量多的一方勝出（`ChineseScript.detect`）。
  - 小說：`detectLanguage` 會回報 zh-Hant 或 zh-Hans；找不到這類字時視為簡體，與過去相同。
  - 漫畫：來源只標 `zh` 且 App 語言是中文時，會先用中文辨識模型（PP-OCRv5）讀前幾頁再判斷（manga-ocr 分不出簡繁）。與 App 同一種寫法就不翻譯，另一種寫法則在讀者開啟上述設定後才自動轉換。中文辨識包還沒下載，或讀不出足夠的字時，不會自動開始。
